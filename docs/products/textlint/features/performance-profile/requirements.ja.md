# パフォーマンスプロファイル

[English](requirements.md)

## この文書について

パフォーマンスプロファイルは、textlint の 1 回の実行の時間がどこに使われたかを示します。遅い実行の理由を説明し、改善すべき部分を見つけられるようにするためです。
textlint はファイルごとに複数の種類の処理をします。プラグインがテキストを TxtAST にパースし、カーネルが木をトラバースして各ノードでルールのリスナーを呼び、ルールがそれぞれのチェックをします。
どれも遅い部分になりうるので、プロファイルはそれらを分けて、設定の読み込みや結果の整形といった周辺の処理とあわせて示します。
親の Product は [textlint](../../product.ja.md) です。

### 範囲

- `textlint --profile` が出力する要約：フェーズ、パーサー、ルール、ファイル
- Markdown と JSON の要約
- プロファイルを使う実行と使わない実行での、プロファイルのコスト
- プログラムが `@textlint/kernel` のプロファイラーから得る集計

### 範囲外

- textlint がどれだけ速く Lint するか。この機能はそれを測り、定めない。
- `node --cpu-prof` のような JavaScript エンジンの CPU プロファイル。これは関数を示し、この機能は textlint の処理（フェーズ、パーサー、ルール）を示す。CPU プロファイルは [変更の比較](../change-comparison/requirements.ja.md) が集める。
- 安定した数値を得るために実行時間を何度も測ること。hyperfine のようなベンチマークツールが行う。プロファイルは 1 回の実行を説明する。
- textlint の 2 つのビルドを比べること。[変更の比較](../change-comparison/requirements.ja.md) が扱う。
- ブラウザーでのプロファイル。カーネルはブラウザーでも動くが、要約を出力するのは CLI だけ。

## ユーザーストーリー

### 実行の時間がどこに使われたかを見る

textlint の開発者や、実行が遅い利用者として、実行の各フェーズの時間がほしい。Node.js の起動と textlint の読み込み、設定の読み込み、ファイルの検索、パース、木のトラバース、ルールの実行、整形のどこを見ればよいかがわかるようにするためです。

**受け入れ条件：**

シナリオ：`--profile` を指定したとき、要約が各フェーズの時間を示す

- Given: ディレクトリに Markdown ファイルと、ルールを持つ設定がある
- When: 開発者が `textlint --profile docs/` を実行する
- Then: 標準出力は Markdown の要約を持ち、Lint 結果を持たない。要約は合計時間と Lint したファイルの数から始まり、各フェーズの行に、時間、合計時間に対する割合、実行回数を持つ

シナリオ：ファイルの数が増えても、要約の大きさは増えない

- Given: 10 ファイルのディレクトリと、10,000 ファイルのディレクトリがある
- When: 開発者がそれぞれのディレクトリで `textlint --profile` を実行する
- Then: 両方の要約は同じセクションを持ち、ルールとファイルのセクションはそれぞれ最大 10 行

### パーサー、トラバース、ルールを区別する

パーサーやカーネルを変更する開発者として、パースの時間、木をトラバースしてリスナーを呼ぶ時間、ルールの時間を別々の数値で見たい。自分の変更が時間のかかる部分にあるかがわかるようにするためです。

**受け入れ条件：**

シナリオ：2 つの形式のファイルを Lint したとき、要約がプラグインごとのパース時間を示す

- Given: ディレクトリに Markdown ファイルとプレーンテキストのファイルがある
- When: 開発者がそのディレクトリで `textlint --profile` を実行する
- Then: 要約は、ファイルをパースした各プラグインの行に、パース時間とパースしたファイルの数を持つ

シナリオ：ルールが遅いとき、そのルールがルールの先頭になる

- Given: 設定が、実行の時間の大半を使うルールを持つ
- When: 開発者が `textlint --profile` を実行する
- Then: そのルールがルールの最初の行で、時間、合計時間に対する割合、リスナーが呼ばれた回数を持つ

### プログラムや AI エージェントからプロファイルを読む

性能を調べる AI エージェントやスクリプトとして、プロファイルのすべての数値を JSON でほしい。表をパースせずに実行を比べられるようにするためです。

**受け入れ条件：**

シナリオ：`--profile` と `--format json` を指定したとき、要約はすべてのルールを持つ JSON になる

- Given: ディレクトリに Lint するファイルと設定がある
- When: エージェントが `textlint --profile --format json docs/` を実行する
- Then: 標準出力は、`total`、`files`、`phases`、`parsers`、`rules`、`slowestFiles` を持つ 1 つの JSON オブジェクトである。`rules` は実行したすべてのルールとフィルタールールを時間の順に持つ。`slowestFiles` は最大 10 ファイル

シナリオ：`--profile` と `--output-file` を指定したとき、Lint 結果はファイルに、要約は標準出力に出る

- Given: ディレクトリに Lint するファイルと設定がある
- When: 開発者が `textlint --profile --output-file result.txt docs/` を実行する
- Then: ファイルは `--format` の形式の Lint 結果を持つ。標準出力は要約だけを持つ

### プロファイルを使わないときはコストを払わない

プロファイルを見ない利用者として、`--profile` なしの実行が、この機能のない textlint の実行と同じ速さであってほしい。

**受け入れ条件：**

シナリオ：`--profile` を指定しないとき、何も記録されず、要約も出力されない

- Given: ディレクトリに Lint するファイルと設定がある
- When: 利用者が `textlint docs/` を実行する
- Then: 標準出力は Lint 結果だけを持つ。プロファイラーは集計を持たない

シナリオ：`--profile` を指定しないとき、この機能によって実行時間は変わらない

- Given: この機能のコードだけが異なる textlint の 2 つのビルドと、数千ファイルのディレクトリがある
- When: それぞれのビルドで、`--profile` なしで交互に何度もそのディレクトリを Lint する
- Then: 実行時間の中央値の差は、同じビルドの 2 系列の実行の差の範囲に収まる

## 機能要件

### 実行の要約

**概要：** Lint 結果の代わりに、実行の時間がどこに使われたかの要約を出力する。

**入力：** `--profile` と、Lint するファイルまたは STDIN の内容。`--fix` の有無は問わない。`--format json` は JSON を選び、それ以外の形式は Markdown を選ぶ。

**出力：** 標準出力の要約。Lint 結果は出力しない。終了ステータスは `--profile` なしの実行と同じ。

#### 適用条件

##### `--profile` が変えること

`--profile` 付きの実行はプロファイルを見るためのものなので、標準出力は要約という 1 つの文書だけを持ちます。
実行はフォーマッターや修正したファイルの書き込みも含めて最後まで進むので、要約はそれぞれの時間を持ちます。
`--output-file` を指定すると、Lint 結果は `--profile` なしのときと同じくファイルに書かれます。

##### フェーズ

| フェーズ | 対象 | 時間の数え方 |
| --- | --- | --- |
| startup | Node.js の起動と textlint のモジュールの読み込み。CLI が Lint を始めるまで | 1 回 |
| load-config | 設定、ルール、フィルタールール、プラグインの読み込み | 1 回 |
| search-files | 引数に一致するファイルの検索 | 1 回 |
| lint（`--fix` では fix） | すべてのファイルの Lint。最初のファイルから最後の結果まで | 1 回 |
| parse | プラグインがテキストを TxtAST にパースする | ファイルの合計。lint の中 |
| traverse | カーネルが木を歩き、各ノードでリスナーを呼ぶ。リスナーの中の時間は含まない | ファイルの合計。lint の中 |
| rules | ルールのリスナー | ルールの合計。lint の中 |
| filter-rules | フィルタールールのリスナー | フィルタールールの合計。lint の中 |
| post-process | プラグインとカーネルがファイルのメッセージを処理する | ファイルの合計。lint の中 |
| apply-fixes | `--fix` で、ルールの修正をテキストに適用する | ファイルの合計。lint の中 |
| format | フォーマッターが出力を作る | 1 回 |
| write-files | `--fix` で `--dry-run` でないとき、修正したファイルを書き込む | 1 回 |

別のフェーズの中で実行されるフェーズは、その下に `depth` 1 で示します。lint の時間は、その中のフェーズとファイルを読む時間を含みます。
textlint はファイルを並行して Lint するので、lint の中のフェーズは各ファイルの時間の合計であり、実時間の区間ではありません。

##### ルールの時間

ルールの時間は、リスナーの開始から、リスナーが返した Promise が終わるまでの時間です。
あるルールの時間に別のルールの時間が混ざらないように、プロファイルが有効な間はリスナーを 1 つずつ実行します。
これにより並行するリスナーの処理の順序は変わりますが、実行のメッセージは変わりません。

##### 要約のセクション

| セクション | 行 | 行の値 | Markdown の行数 | JSON の行数 |
| --- | --- | --- | --- | --- |
| Phases | 実行したフェーズ | 時間、合計時間に対する割合、回数 | すべて | すべて |
| Parsers | ファイルをパースしたプラグイン | 時間、パースしたテキストの数 | すべて | すべて |
| Rules | 実行したルールまたはフィルタールール | 時間、合計時間に対する割合、リスナーの呼び出し回数 | 時間の長い 10 件 | すべて |
| Files | Lint したファイル | そのファイルの parse、traverse、ルール、フィルタールール、post-process の時間 | 時間の長い 10 件 | 時間の長い 10 件 |

##### 要約のテキスト

時間はミリ秒で、小数点以下 2 桁です。
ファイルパスはカレントディレクトリからの相対パスです。
ファイルパスと ID の中の、表を壊す文字や端末を制御する文字は、エスケープするか取り除きます。

#### 例外時の挙動

##### 実行が失敗する

失敗までに記録した内容で要約を標準出力に出力し、続いてエラーを標準エラー出力に出力する。

### プロファイルのコスト

**概要：** プロファイルは無効なときほとんどコストがなく、有効なときも通常の実行に近い。

**入力：** `--profile` の有無にかかわらない実行。

**出力：** なし。実行時間に対する制約である。

#### 適用条件

##### プロファイルが無効なとき

`--profile` なしの実行には、この機能による測定できる性能の低下がありません。カーネルは、ファイルごととリスナーごとに 1 回だけプロファイルが有効かを確かめ、ノードごとには何もしません。

##### プロファイルが有効なとき

`--profile` 付きの実行は、リスナーの呼び出しごとに時計を読み、リスナーを 1 つずつ実行するので、`--profile` なしの実行より長くなることがあります。
数値は 1 回の実行を説明します。`--profile` なしの実行時間は [変更の比較](../change-comparison/requirements.ja.md) が測ります。

### プログラム向けの集計

**概要：** カーネルを実行するプログラムは、要約の元になる集計を得られる。

**入力：** プログラムが `@textlint/kernel` のプロファイラーを有効にして Lint する。

**出力：** 集計のリスト。集計は、種類（何を測ったか）、ID（プラグイン ID、ルール ID、ファイルパス。対象のないフェーズにはない）、回数、合計時間、1 回の記録の最長時間を持つ。

#### 適用条件

プロファイラーは集計だけを持つので、リストの大きさはフェーズ、プラグイン、ルール、ファイルの数で決まり、実行された回数では決まりません。
プロファイラーを無効にすると集計は消えます。

## データ要件

### 必要なデータ

- **種類と ID ごとの集計：** 回数、合計時間、最長時間。プロセスの間メモリーに保つ。

### 関係

ファイルの集計は、そのファイルについて記録した parse、traverse、ルール、フィルタールール、post-process の集計の合計です。

### 個人情報

収集しません。要約はファイルパスとプラグインとルールの ID を持ち、ファイルの内容は持ちません。

## 外部サービスへの依存

なし。

## セキュリティの考慮事項

ファイル名はどんな文字も持ちえ、要約はファイルパスを端末に出力します。要約は Markdown の表を壊す文字をエスケープし、制御文字を取り除くので、ファイル名で端末の出力を書き換えることはできません。
要約はファイルの内容やルールのメッセージを持ちません。
