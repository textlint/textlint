# ルールの 1 回生成

[English](requirements.md)

## この文書について

ルールは通常、ファイルごとにリスナーを作る。textlint は新しい context でルール関数を呼び、ルールは新しいリスナー関数を返す。
数十のルールで数千のファイルを Lint すると、この生成と、それが残すゴミの回収が、実行の中で目に見える割合になる。
ルールの 1 回生成は、ルールがリスナーを 1 回だけ作り、すべてのファイルで使い回せるようにする。
TxtAST のルートは必ず `Document` なので、`Document` と `Document:exit` のリスナーは各ファイルの最初と最後に必ず呼ばれ、ルールはそこで状態をリセットする。
ルールは `createOnce` を持つことで利用を選び、持たないルールはこれまでどおり動く。
親の Product は [textlint](../../product.ja.md)。

### 範囲

- ルール関数の `createOnce` プロパティと、textlint がそれをルールモジュールや、修正できるルールの `linter` と `fixer` の関数から見つける方法
- `Document` のリスナーで、ファイルごとにルールの状態をリセットすること
- `createOnce` が受け取る context と、そのメソッドがどのファイルを指すか
- 作ったルールをどれだけの間使い回すか
- リスナーが同期的に終わらなければならないルール
- `createOnce` のない textlint でも動くルール

### 範囲外

- フィルタールール。これまでどおりファイルごとに作る。
- 非同期のルール。リスナーが Promise を返すルールは、`createOnce` のないルール関数のまま使う。
- 他のリンターの `before` や `after` のような、ファイルの前後のフック。`Document` と `Document:exit` のリスナーがその役割を持つ。
- ルールが見るノードのないファイルで、ファイルやルールを飛ばすこと。
- ルールを変換するヘルパーのパッケージ。委譲する関数はルール自身が書ける。

## ユーザーストーリー

### 多くのファイルでルールを安く動かす

ルールの作者として、リスナーを 1 回だけ作りたい。多くのファイルを Lint するときに、ファイルごとにリスナーを作るコストを払わないようにするためです。

**受け入れ条件：**

シナリオ：ルールが `createOnce` を持つとき、多くのファイルの実行で 1 回だけ呼ばれる

- Given: ルール関数が `createOnce` を持ち、設定がそのルールを有効にしている
- When: 書き手が 100 個の Markdown ファイルのディレクトリで `textlint` を実行する
- Then: `createOnce` は 1 回呼ばれる。ルール関数自体は呼ばれない。`createOnce` が返したリスナーはすべてのファイルのノードで呼ばれ、メッセージはルール関数をファイルごとに呼んだときと同じ

シナリオ：同じルールが 2 つの異なるオプションで有効なとき、それぞれが 1 回作られる

- Given: プリセットが同じルールモジュールを異なるオプションで 2 回有効にしている
- When: 書き手が 10 ファイルのディレクトリで `textlint` を実行する
- Then: `createOnce` は 2 回、それぞれのオプションで呼ばれる。作られたルールは、それぞれ自身のルール ID で報告する

シナリオ：プログラムがテキストごとに新しいルールのオブジェクトでカーネルを呼ぶとき、ルールはテキストごとに作られる

- Given: プログラムが 2 つのテキストで `TextlintKernel#lintText` を呼び、毎回新しいオブジェクトの新しい `rules` 配列を渡す
- When: プログラムが 2 つのテキストを Lint する
- Then: `createOnce` はテキストごとに 1 回呼ばれる。メッセージは同じオブジェクトを渡したときと同じ

### ファイルごとにルールの状態をリセットする

ファイルの中で何かを数えるルールの作者として、各ファイルの最初に状態をリセットしたい。あるファイルの状態が次のファイルに持ち越されないようにするためです。

**受け入れ条件：**

シナリオ：`Document` のリスナーがカウンターをリセットするとき、各ファイルは 0 から始まる

- Given: `createOnce` を持つルールが見出しを数え、`Document` のリスナーで数をリセットし、数が 10 を超えると `Document:exit` のリスナーで報告する
- When: 書き手が見出しを 6 個ずつ持つ 2 つのファイルを Lint する
- Then: どちらのファイルにもメッセージは報告されない

シナリオ：ファイルにルールが見る他のノードがないとき、`Document` のリスナーは呼ばれる

- Given: `createOnce` を持つルールが `Table` と `Document:exit` を見て、`Document:exit` でファイルごとに 1 つのメッセージを報告する
- When: 書き手が表のないファイルを Lint する
- Then: ファイルは `Document:exit` からの 1 つのメッセージを持つ

### 今のファイルの context から報告する

ルールの作者として、`context` のメソッドが Lint 中のファイルを指してほしい。`createOnce` が受け取った context をそのまま持っておけるようにするためです。

**受け入れ条件：**

シナリオ：リスナーが `report` を呼ぶとき、メッセージは今のファイルに属する

- Given: `createOnce` を持つルールが `context.report` と `context.getSource` を変数に持っておく
- When: 書き手が 2 つのファイルを Lint し、ルールが両方で報告する
- Then: 各メッセージは、報告したノードのファイルの結果にあり、そのファイルでの行と列を持つ。`getSource()` はそのファイルのテキストを返す

シナリオ：`createOnce` がファイルを必要とするメソッドを呼ぶとき、エラーがルールを示す

- Given: ルールが `createOnce` の本体で、リスナーの外で `context.getSource()` を呼ぶ
- When: 書き手が `textlint` を実行する
- Then: 実行は、ルール ID を示し、そのメソッドはリスナーの中でだけ呼べると説明するエラーで失敗する

シナリオ：`createOnce` がファイルに依存しない値を読むとき、値を使える

- Given: ルールが `createOnce` の本体で `context.Syntax`、`context.RuleError`、`context.fixer`、`context.locator`、`context.id`、`context.severity` を読む
- When: 書き手が `textlint` を実行する
- Then: 値は `createOnce` のないルール関数と同じで、実行は成功する

### 非同期のルールが別のファイルに報告しないようにする

書き手として、Promise を返す `createOnce` のルールにははっきり失敗してほしい。そのメッセージが別のファイルに入らないようにするためです。

**受け入れ条件：**

シナリオ：`createOnce` を持つルールのリスナーが Promise を返すとき、Lint はエラーで失敗する

- Given: `createOnce` を持つルールが、Promise を返すリスナーを持つ
- When: 書き手がそのノードを持つファイルを Lint する
- Then: そのファイルの Lint は、ルール ID を示し、`createOnce` のリスナーは同期的でなければならないと説明するエラーで失敗する。そのルールのメッセージは他のファイルにない

### 古い textlint と新しい textlint で同じルールを公開する

ルールの作者として、`createOnce` のない textlint でもルールが動いてほしい。利用者が新しいルールを使うために textlint を更新しなくて済むようにするためです。

**受け入れ条件：**

シナリオ：ルール関数が `createOnce` に委譲するとき、古い textlint はそれをファイルごとに実行する

- Given: ルール関数が `createOnce(context, options)` を返し、`createOnce` をプロパティに持つ
- When: `createOnce` のない textlint が 2 つのファイルを Lint する
- Then: メッセージは `createOnce` のある textlint と同じ

### 1 回作ったルールで修正する

書き手として、`textlint --fix` が `createOnce` を持つルールでも動いてほしい。修正できるルールも `createOnce` を使えるようにするためです。

**受け入れ条件：**

シナリオ：修正できるルールが `linter` と `fixer` に `createOnce` を持つとき、`--fix` はその修正を適用する

- Given: 修正できるルールが、`linter` と `fixer` の関数に `createOnce` を持つ
- When: 書き手が、そのルールが修正できるエラーを 2 つ持つファイルで `textlint --fix` を実行する
- Then: ファイルは修正され、結果は `createOnce` のないルールと同じ

## KPI

### 1 回生成するルールでの実行時間

- **目標値：** [変更の比較](../change-comparison/requirements.ja.md) の huge のセットを preset-jtf-style で Lint したとき、ルールが `createOnce` を持つほうが持たないほうより、同じビルドの 2 回の計測の差を超えて速い
- **計測方法：** 同じビルドと 2 つの版のルールで同じ文書を交互に Lint し、実行時間の中央値を比べる
- **計測時期：** プリセットが `createOnce` を採用するとき

## 機能要件

### ルールを 1 回作る

**概要：** textlint はルールの `createOnce(context, options)` を 1 回呼び、返されたオブジェクトをすべてのファイルで使い回す。

**入力：** ルール関数、または `linter` と `fixer` の関数が、`createOnce` 関数をプロパティに持つルールモジュール。設定からのルールのオプション。

**出力：** 各ファイルのメッセージ。ルール関数をファイルごとに呼んだときと同じ。

#### 適用条件

##### textlint がどの関数を使うか

textlint は、そのファイルで呼ぶ関数が関数の `createOnce` プロパティを持つとき、`createOnce` を使う。
修正できるルールでは、Lint は `linter` の `createOnce` を、修正は `fixer` の `createOnce` を使う。それぞれ別に作る。
プロパティがないとき、textlint はこれまでどおりファイルごとにルール関数を呼ぶ。

##### 作ったルールをどれだけの間使い回すか

作ったルールは、同じカーネルが同じルールのエントリーのオブジェクト(ルールとそのオプションを持つ)で Lint する間、使い回す。
CLI と `createLinter` はすべてのファイルに同じエントリーを渡すので、1 回の実行で各ルールは 1 回作られる。
新しいエントリーは、ルールを作り直す。

##### リスナー

`createOnce` が返すオブジェクトは、ルール関数が返すのと同じく、ノードの種類ごとのリスナーを持つ。
textlint はすべてのファイルのノードでそれらを呼ぶ。
ファイルごとの状態を持つルールは、各ファイルで最初に呼ばれる `Document` のリスナーで状態をリセットし、最後に呼ばれる `Document:exit` のリスナーで仕上げる。

##### Context

`createOnce` が受け取る context は、すべてのファイルで同じオブジェクトである。
`id`、`severity`、`Syntax`、`RuleError`、`fixer`、`locator` はファイルに依存せず、どこでも使える。
`report`、`getSource`、`getFilePath`、`getConfigBaseDir` は Lint 中のファイルを指し、リスナーの中で使える。

##### 同期的なリスナー

カーネルは多くのファイルを同時に Lint し、context は一度に 1 つのファイルを指す。
`createOnce` を持つルールのリスナーは、同期的に終わらなければならない。

#### 例外時の動作

##### ファイルの外でファイルのメソッドを呼ぶ

ルールのファイルを Lint していないときに `report`、`getSource`、`getFilePath`、`getConfigBaseDir` を呼ぶと、ルール ID を持つエラーを投げる。実行は、ルールが投げた他のエラーと同じく失敗する。

##### リスナーが Promise を返す

`createOnce` を持つルールのリスナーが thenable を返すと、そのファイルの Lint はルール ID を示すエラーで失敗する。

##### `createOnce` が例外を投げる

`createOnce` が例外を投げると、エラーメッセージは、例外を投げたルール関数と同じくルールを示す。何も作られていないので、textlint は次のファイルで `createOnce` をもう一度呼ぶ。

## データ要件

### 必要なデータ

- **作ったルール：** `createOnce` が返したオブジェクトとその context。カーネルが、ルールのエントリーが使われる間、エントリーごとに持つ。

### 関係

作ったルールは、1 つのカーネルと 1 つのルールのエントリーに属する。修正できるルールは、Lint 用と修正用に 1 つずつ作ったルールを持つ。

### 個人情報

なし。
