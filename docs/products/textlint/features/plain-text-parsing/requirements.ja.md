# プレーンテキストのパース

[English](requirements.md)

## この文書について

プレーンテキストのパースは、プレーンテキストを TxtAST に変換します。どの形式向けに書かれたルールでもチェックできるようにするためです。
プレーンテキストにはマークアップがないので、パーサーが認識する構造は行だけです。
この機能は `@textlint/text-to-ast` が提供し、組み込みの `@textlint/textlint-plugin-text` が使います。
親の Product は [textlint](../../product.ja.md) です。

このパーサーは、TxtAST のパーサーのもっとも小さな例でもあります。
使う汎用ノードは 4 つだけで、プラグインの作者はこれを読んで、パーサーが何を出力すべきかを学べます。
この文書とパーサーを並べて読めるように、挙動はシンプルに保ちます。

この文書は、テキストのどの部分がどのノードになるか、そして各ノードの位置を定義します。
共通のプロパティや位置の規約のように、すべての TxtAST が満たすことは [TxtAST](../txtast/requirements.ja.md) が定義します。

### 範囲

- `parse(text)` 関数
- 各行と各改行がなるノードと、その範囲
- 改行、空のテキスト、BOM
- 組み込みのプラグインが扱うファイルの拡張子

### 範囲外

- Markdown と、マークアップを持つほかの形式。[Markdown のパース](../markdown-parsing/requirements.ja.md) を参照
- プレーンテキストの中から、複数行の段落、見出し、リスト、インデントを認識すること
- 文章を文や単語に分割すること。これはルールが、文の分割器や形態素解析器などを使って行う
- バイト列を文字列にデコードすること。パーサーは文字列を受け取る
- すべての形式で共通のプロパティと規約。[TxtAST](../txtast/requirements.ja.md) を参照

## ユーザーストーリー

### プレーンテキストのファイルを行ごとにチェックする

書き手として、テキストファイルの各行を文章としてルールに渡してほしい。Markdown に使っているルールで、テキストファイルもチェックできるようにするためです。

**受け入れ条件：**

シナリオ：テキストが 2 行のとき、各行が段落になる

- Given: 行が `first line` と `second line` のテキスト
- When: テキストをパースする
- Then: `Document` は各行の `Paragraph` と、その間の `Break` を持ち、各 `Paragraph` は行全体を `value` とする 1 つの `Str` を持つ

シナリオ：行が Markdown のように見えるとき、テキストのまま残る

- Given: 行 `# Title with *emphasis*`
- When: テキストをパースする
- Then: その行は 1 つの `Str` を持つ 1 つの `Paragraph` になり、`value` は `#` と `*` を保つ

シナリオ：行が空のとき、段落にならない

- Given: `a`、空行、`b` からなるテキスト
- When: テキストをパースする
- Then: `Document` の子は `Paragraph`、`Break`、`Break`、`Paragraph` で、空の `Str` を持つ `Paragraph` はない

### 正しい位置を報告する

ルールの作者として、すべてのノードが元のテキストを正確に指してほしい。ファイルがどの改行を使っていても、エラーと修正が正しい文字に当たるようにするためです。

**受け入れ条件：**

シナリオ：どのテキストをパースしても、AST は TxtAST の位置の規約に従う

- Given: すべての種類の改行、タブ、サロゲートペアを含むテキストを含む、任意のテキスト
- When: テキストをパースする
- Then: `@textlint/ast-tester` がその AST を受け入れる

シナリオ：テキストが単独の `\r` を使うとき、その文字で行が終わる

- Given: `a`、単独の `\r`、`b` からなるテキスト
- When: テキストをパースする
- Then: `Document` の子は `Paragraph`、`Break`、`Paragraph` で、2 つ目の `Paragraph` は 2 行目の 0 列目から始まる

シナリオ：行に U+2028 または U+2029 があるとき、その文字は行に残る

- Given: `a`、U+2028、`b` からなるテキスト
- When: テキストをパースする
- Then: テキストは 1 つの `Paragraph` になり、その `Str` は U+2028 を含む。エディターが 1 行として表示するとおりである

シナリオ：テキストが `\r\n` を使うとき、その改行は 1 つの `Break` になる

- Given: テキスト `a\r\nb`
- When: テキストをパースする
- Then: `Break` の `raw` は `\r\n` で、その `range` は 2 文字にわたり、2 つ目の `Paragraph` は 2 行目の 0 列目から始まる

シナリオ：テキストが改行で終わるとき、各改行は `Break` になる

- Given: `a` の後に `\n` が 2 つ続くテキスト
- When: テキストをパースする
- Then: `Document` の子は `Paragraph`、`Break`、`Break` で、`Document` の `loc.end` は 3 行目の 0 列目になる

シナリオ：テキストが BOM で始まるとき、位置は BOM を無視する

- Given: U+FEFF で始まるテキスト
- When: テキストをパースする
- Then: AST は BOM のないテキストのものと同じになり、位置は textlint がルールに渡すテキストと一致する

### パーサーの書き方を学ぶ

プラグインの作者として、出力を予想しやすい小さなパーサーがほしい。自分の形式向けのパーサーを書く前に、TxtAST のパーサーが何を出力すべきかを知るためです。

**受け入れ条件：**

シナリオ：AST を読むと、汎用ノードだけを使っている

- Given: 任意のテキスト
- When: テキストをパースする
- Then: AST は `Document`、`Paragraph`、`Str`、`Break` だけを含み、すべてのノードは共通のプロパティと、`Document` と `Paragraph` では `children`、`Str` では `value` だけを持つ

シナリオ：この文書を読むと、テキストの AST を手で書ける

- Given: テキストと [ノードの表](#ノード)
- When: 読み手が表に従って期待する AST を書く
- Then: `parse` が返す AST は、それと同じになる

### 既存のルールを動かし続ける

ルールの作者として、プレーンテキストの AST が安定していてほしい。textlint が更新された後も、公開したルールが動き続けるようにするためです。

**受け入れ条件：**

シナリオ：textlint がマイナーまたはパッチバージョンで更新されたとき、テキストの AST は変わらない

- Given: テキストと、ある textlint のバージョンがそれに対して出力する AST
- When: そのテキストを後のマイナーまたはパッチバージョンでパースする
- Then: AST のノードの種類、プロパティ、位置は同じである。それらの変更はメジャーバージョンでだけ現れ、そのリリースノートに載る

### 信頼できない投稿者のテキストファイルをチェックする

CI で textlint を実行する書き手として、どのテキストファイルも大きさに比例する時間でパースしてほしい。プルリクエストがチェックを止められないようにするためです。

**受け入れ条件：**

シナリオ：テキストを長くすると、パースの時間は大きさに比例して増える

- Given: 多くの行からなるテキスト、または改行のない 1 行
- When: テキストを 4 倍の長さにしてパースする
- Then: パースにかかる時間は 16 倍ではなく、およそ 4 倍になる

## KPI

### TxtAST の規約への適合

- **目標値：** すべてのテストフィクスチャと、実際のテキストからなるコーパスのすべてのファイルについて、`@textlint/ast-tester` が AST を受け入れること。
- **測定方法：** フィクスチャ、少数の行と改行のすべての組み合わせ、コーパスをパースし、各 AST にテスターを実行する。
- **測定時期：** パーサーを変えるとき。

### パースの速度

- **目標値：** 同じコーパスで前のリリースより遅くならないこと。速いほうが望ましい。
- **測定方法：** 実際の文書からなるコーパスをループしてパースし、前のリリースと変更後の中央値を比べる。
- **測定時期：** パーサーの実装を変えるとき。

### 依存

- **目標値：** 実行時の依存は `@textlint/ast-node-types` だけであること。
- **測定方法：** パッケージの `dependencies` を読む。
- **測定時期：** パッケージの依存を変えるとき。

## 機能要件

### プレーンテキストを TxtAST にパースする

**概要：** `parse(text)` はテキスト全体を含む `Document` ノードを返す。

**入力：** 文字列。空でもよく、BOM で始まってもよい。

**出力：** [TxtAST](../txtast/requirements.ja.md) に従う `Document` ノード。

#### 適用条件

##### 行

行は、[TxtAST](../txtast/requirements.ja.md) の位置の規約が定める改行で終わる。LF（`\n`）、CR（`\r`）、CRLF（`\r\n`）である。CRLF は 1 つの改行である。
U+2028 や U+2029 のようなほかの文字は、行の文字である。
プレーンテキストには独自の構文がないので、テキストの行がそのまま `loc` の行である。

段落は 1 行である。
プレーンテキストには、どの行が段落をなすかを決める決まりがなく、行はすべてのプレーンテキストが持つ唯一の構造である。
そのため、空行で区切られていない行どうしであっても、パーサーは行をつなげない。

##### ノード

| テキストの部分 | ノード | プロパティ | 範囲 |
| --- | --- | --- | --- |
| テキスト全体 | `Document` | | 0 からテキストの終わりまで |
| 空でない行 | `Paragraph` | | 行の最初の文字から行の終わりまで。改行は含まない |
| `Paragraph` の内容 | `Str` | `value`: 書かれたとおりの行 | その `Paragraph` と同じ |
| 改行 | `Break` | | その改行 |

- `Document` の子は、元のテキストの順に並ぶ `Paragraph` と `Break` である。
- `Paragraph` はちょうど 1 つの子として `Str` を持つ。
- 段落は 1 行で、改行を含むことがないので、`Break` は `Paragraph` ではなく `Document` の子である。
- 空行の改行やテキストの末尾の改行も含めて、すべての改行が `Break` になる。
- 空行はそれ自身のノードを持たない。その改行だけが `Break` になる。
- 空白やタブだけの行は空ではない。`Paragraph` になり、その `Str` は空白とタブを保つ。
- `Str` の `value` はその `raw` と等しい。何もデコードせず、何も取り除かない。

##### ファイルの拡張子

組み込みのプラグインは、拡張子が `.txt` と `.text` のファイルと、`extensions` オプションが追加する拡張子のファイルを扱う。

#### 例外時の挙動

##### 空のテキスト

テキストが空のとき、`Document` は子を持たず、その `range` は `[0, 0]` で、`loc.start` と `loc.end` はどちらも 1 行目の 0 列目である。

##### 改行で終わるテキスト

テキストが改行で終わるとき、`Document` の `loc.end` は、最後の改行の次の行の 0 列目である。

##### BOM

テキストの先頭の BOM は、パースの前に取り除く。
オフセットは BOM を数えず、`Document` の `raw` は BOM を含まない。
textlint もルールに渡すテキストから BOM を取り除くので、位置は一致する。

##### 不正なテキスト

プレーンテキストに構文エラーはない。`parse` は、単独のサロゲートや U+0000 を含む文字列を含め、どの文字列に対しても例外を投げない。

## データ要件

### 必要なデータ

- **ソーステキスト：** `parse` に渡された文字列。`parse` が返った後は保持しない。

### 関係

`Document` を除く各ノードは、ちょうど 1 つの親を持つ。ノードの子は元のテキストの順に並ぶ。

### 個人情報

なし。パーサーはデータを集めず、保持しない。

## 外部サービスへの依存

なし。パースはローカルで動き、ネットワークのサービスを使わない。

## セキュリティの考慮事項

textlint は CI で、信頼できない投稿者のファイルに対して実行される。そのため、細工されたテキストや特殊なテキストがパースを止めてはならない。
パースの時間は、テキストの大きさに比例していなければならない。
AST の深さは、テキストによらず最大 3 階層（`Document`、`Paragraph`、`Str`）なので、textlint とルールは再帰でたどることができる。
`parse` の呼び出しはそれぞれ独立している。結果は前にパースしたテキストに依存しない。
